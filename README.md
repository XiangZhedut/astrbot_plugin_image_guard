# 图片历史管理器 · Image History Manager

按日期浏览 AstrBot 的上下文图片，保留副本、移除图片引用、管理回收站，并在发送前阻止禁发图片再次发送。

例如：表情包库已删除并拉黑某张照片，但 Agent 还记得它在临时目录里的旧路径，调用 `send_message_to_user` 重发。本插件在实际发送路径补上检查。

## 功能

- WebUI 扩展功能中的「图片历史管理」相册：日期分组、群聊/日期/文件名筛选、分页、缩略图、详情和批量操作。
- 「收纳表情包」开关默认关闭，可在相册顶部即时切换或在插件配置调整。关闭时普通相册/上下文/相似整理隐藏表情包，不额外保存其新副本；已有图片不自动删除。
- 「表情包」分类仍可查看并管理被筛出的图片，支持批量「标为表情包」「当作普通图片」，详情可恢复自动判定；已禁发、已保留和回收站始终可管理。
- 同一张图片可关联多个来源群；QQ 官方适配器按成员分开的群会话会合并。支持仅在相册内备注群名；私聊和缺少来源的临时文件列入「未关联群聊」。
- 默认开启跨群/跨会话图片隔离：实际接收过图片的会话才可重发，未知来源与未知目标拒发。覆盖普通、主动、流式回复和发消息工具指定会话，管理员同样受限。
- 拦截是本轮终止结果：工具返回 `retryable=false`，后续工具不再执行发送，本轮生成回复替换为固定提示，不鼓励重发、重新上传或换格式/路径/群重试；同一会话本轮至多提示一次。新消息、新会话互不影响。
- 「相似图片整理」按整张图的比例、边缘与颜色生成候选组；可选择本组当前页，批量保留、禁发、移除引用或移入回收站，不自动删图。
- 「已禁发」同时管理原图、被规则覆盖的转码版本及待核对候选；详情展示命中来源规则，解除来源规则须明确确认影响范围。
- 关联 AstrBot 4.29.3 SQLite 的 AI 对话与平台消息历史，以及 `data/temp/` 中的本地图片；同文件去重。
- 「保留」保存独立副本并保护它免于删除操作；「移除上下文」仅替换选中图片引用，不删除整段聊天。
- 「移入回收站」可同时移除上下文和禁发；「恢复」不会覆盖已更新的记录；「彻底删除」需要输入确认文字。
- 面板的「测试禁发规则」只检查规则，不向 QQ 等平台试发图片。
- 检查普通回复、`event.send()`、`send_streaming()`、平台 `send_by_session()` 和内置 `send_message_to_user`。
- 同步 **表情包小偷 `astrbot_plugin_stealer`** 的 SHA-256 黑名单，只读原数据库。
- 独立禁发列表：文件 SHA-256、首帧像素指纹；默认增加比例、dHash 与 RGB 缩略指纹联合匹配，覆盖常见格式转换、压缩和等比缩放。可另行启用旧版单独 dHash 匹配。
- 支持本地路径、`file:///`、base64、公开 HTTP(S) 图片，以及 Node/Nodes 中的图片。文件附件检查实际内容，改扩展名也不能跳过可解码图片检查。
- 只使用本地图片算法，不调用视觉模型，不上传图片。
- 管理入口仅限 AstrBot 管理员，没有向 LLM 注册添加/解除禁发的工具。
- 拦截不删除原图；卸载时恢复本插件包装的发送方法。

## 使用

打开 WebUI 侧栏「扩展功能 → 图片历史管理」。也可从插件卡片的页面入口打开相册。
首次加载会扫描历史；此后每 2 分钟自动刷新索引，可随时点击「扫描历史」。

顶部「来源群聊」筛选会作用于所有分类（包括已禁发、相似图和回收站）。同图发在多个群时会同时出现在这些群里；群筛选只控制展示范围，禁发规则依旧对所有群和私聊生效，避免换群绕过。旧记录无法恢复来源时不会根据文件名或人物猜测群聊。

**跨群隔离是独立的发送限制。** A 群实际接收的图片不能由机器人发到 B 群或其他私聊；B 群成员实际发送同图后，B 群才有自己的接收记录。只更改相册筛选、备注、保留状态或在 AI 的工具参数/回复中提到旧路径，不会取得转发权限。升级时从平台消息历史的用户图片组件，以及 AI 对话历史中用户消息的结构化图片块恢复接收记录，不把机器人发图、纯文字路径或 AI 历史引用当作授权。

文件/像素精确命中的来源优先于其他群的相似图片；仅靠视觉匹配且涉及多个来源时拒发，避免猜测。来源不明的旧图、公共表情、生成图片等也会被严格模式拦截，需要先在目标会话实际收到该图。选择具体群聊后点「测试禁发规则」，还会显示该群的隔离检查结果，不会真实发图。相册详情列出该图已经确认的接收会话。

即使关闭图片历史副本收集，隔离开启时仍记录接收来源与指纹，不另存新图片副本。关闭「启用图片禁发」总开关或「跨群/跨会话图片隔离」会停用相应发送保护；侧栏显示实际状态。

### 拦截后的反馈

默认反馈为：“这张图片受禁发或会话隔离规则保护，不能发送。本次请求已终止，请勿重复尝试或通过重新上传、改格式、换群等方式重试。”

拦截状态只绑定本轮事件，发送层会抑制本轮后续重试及重复消息；即使模型生成重试建议也会替换。若实际拒发发生在下层适配器，发消息工具也会改为返回不可重试的拒绝结果，不再误报发送成功。最终模型回复和本轮新增的最终助手历史会同步改为提示。旧历史不批量改写，已经送出的文字/流式片段不能追溯撤回。设置空提示仍保持静默，不能借此发送模型生成的重试建议。

### 图片如何归纳

- 日期：本地文件时间优先，其次采用聊天记录时间；群聊来自适配器会话信息，保存在本机 SQLite。
- 同文件：SHA-256 文件哈希；格式不同但解码像素相同：校正 EXIF 方向、透明区域合成白底后比较 RGB 像素哈希。
- 相似候选：整图宽高比、9×8 灰度缩略图提取的 64 位 dHash 明暗边缘，以及 16×16 RGB 缩略图颜色差异联合比较。
- 相似组每张图片都须匹配本组代表图，避免靠 A 像 B、B 像 C 就无限合并。候选阈值比发送拦截宽松，需要人工核对，不自动删除。

上述归纳不调用本地大模型、视觉 API 或人脸识别，不按图片中的人物、身份或语义分类。它适合整理同一张图的转码、压缩与缩放版本；不同角度的新照片未必归到一起。聊天系统提示与聊天回复仍属于原有语言模型上下文，按所用语言模型的正常规则计费。

### 是否收纳表情包

相册顶部的「收纳表情包」开关会保存到插件配置，无需重载；历史扫描与新消息收集统一遵守该开关。默认关闭。关闭后的表情仍保留最小指纹和接收来源，保证禁发和跨群隔离生效；不再自动创建新的完整相册副本。已经保存的文件、AstrBot 本身的临时文件和上下文不会自动删除。明确点击「保留」仍可保存一张表情包副本。

判定参考表情包小偷的元信息机制，采用独立实现：OneBot/NapCat 的 `sub_type=1`、`subType=1`、平台表情摘要、商城表情编号与 QQ 商城 CDN 域名。另只读本机表情包小偷 `emoji` 已入库表的文件哈希/来源记录，复用已有判定；不把待审核池或黑名单中的照片一概当作表情包，不写入其数据库。

不会因为图片较小、是 GIF/WebP 或正方形就直接排除。QQ 官方接口常将自制表情当普通图片发送，缺少标记且未在表情库入库时可能漏判。可以选中图片「标为表情包」，误判时到「表情包」分类「当作普通图片」；手动纠正会保留，自动扫描不会覆盖。没有新增视觉模型或收费 API 调用。

在任意图片详情中选择「查看相似图片」可查找该图的转码与近似版本，沿用当前群聊、日期及搜索条件。相似组按整图视觉内容分组，并非人物识别；每个成员须与本组代表图片匹配，不通过相似链无限扩张。不同版本仍是独立图片记录，保留各自格式、群聊来源和上下文引用。

「规则覆盖」表示图片已经被禁发原图的规则拦截；「待核对」只是较宽松的视觉候选，需要核对后单独禁发。解除一张图的独立禁发不一定解除来源规则；详情可查看并确认解除来源规则，其他独立规则和表情包小偷黑名单仍有效。

升级时会保留已有数据库和禁发列表，并尝试用本机原图补全旧规则的视觉指纹；若原图已经丢失，面板会提示缺失规则数量，重新提供原图并禁发即可补全。

| 操作 | 结果 |
| --- | --- |
| 保留 | 在插件数据目录保存副本，临时目录被清理后仍可预览；保留中的图片不能直接删除 |
| 禁发 | 保留图片和上下文，阻止标准发送入口发送这张图；与保留状态独立 |
| 移除上下文 | 精确替换 AI 对话及平台历史中的图片引用、已识别的路径与 JSON 工具参数，文字和其他图片不变 |
| 移入回收站 | 移动临时目录/本插件图片库中的匹配文件；默认同时移除上下文并禁发，可以在确认窗口调整 |
| 恢复 | 恢复文件和仍未发生变化的上下文记录；不覆盖同名新文件或新聊天内容，不自动解除禁发 |
| 彻底删除 | 永久删除该图片的回收站文件及本插件的恢复记录，保留禁发指纹；需要输入“彻底删除” |
| 测试禁发规则 | 显示文件/像素/相似指纹或外部黑名单命中原因，不发送消息 |

本地图片优先按原文件日期分组，仅有远程/嵌入引用时使用关联历史的时间，按服务器本地时区显示；会话级历史没有逐条时间时，日期是近似值。界面中的“上下文条数”是引用记录数，不等于消息总数。

**移除引用不等于抹除所有记忆。** 已有文字描述、其他插件的记忆、已发送的 QQ 消息、模型服务商日志不会随之删除。正在执行的请求不能追溯撤回；删除后的后续 LLM 请求会过滤被移除的历史引用。若要阻止重发，请同时禁发。

只支持本机 SQLite 的上述两张标准历史表；其他数据库仍可使用本地图片相册和禁发，不能编辑上下文。不能恢复已被 AstrBot 清理的原图，过期远程地址会显示占位。远程预览会从原图片服务器读取图片，仍受安全地址、大小和超时限制。

管理面板需要登录 AstrBot；任何有该面板访问权限的人均能管理图片，因此不要向群成员共享管理面板。聊天中的管理命令仍仅限 AstrBot 管理员，没有将管理能力注册为 LLM 工具。

先在 AstrBot 的访问控制中设置管理员 ID。QQ 官方机器人使用平台实际提供的 OpenID，不一定是数字 QQ 号。

```text
/禁图 状态
/禁图 添加
/禁图 列表
/禁图 检查
/禁图 解除 <编号>
```

`添加` / `检查` 时附带或引用一张图片；若平台没有提供被引用图片的内容，可在管理员私聊中提供该文件在 AstrBot 本机上的完整路径，例如：

```text
/禁图 添加 /path/to/private-photo.jpg
```

成功后只返回禁发编号，不回发图片。**不要为管理方便把私密图片重新发到公开群里。**
`解除` 仅修改本插件列表。如果原表情包插件仍将图片拉黑，同步开启时会继续拦截。

## 设置

| 设置 | 默认值 | 说明 |
| --- | --- | --- |
| 启用图片禁发 | 开 | 总开关 |
| 收纳表情包 | 关 | 普通相册是否包含表情包，是否自动保存其新副本；可手动纠正，不影响禁发和跨群隔离 |
| 跨群/跨会话图片隔离 | 开 | 实际接收过图片的会话才可重发；未知来源、目标或多来源模糊匹配拒发，公共表情和生成图也受此限制 |
| 收集图片历史 | 开 | 启动/定期扫描与新入 AI 对话图片的本地副本收集；手动扫描仍可用 |
| 图片副本容量上限 | 512 MiB | 达到上限暂停新增副本，不自动删图；回收站另计 |
| 单次扫描临时文件上限 | 5000 | 防止无限扫描临时目录 |
| 同步表情包小偷黑名单 | 开 | 读取其 `cache/emoji.db` 中的黑名单 |
| 阻止转格式、压缩与缩放绕过禁发 | 开 | 整图比例、边缘与 RGB 指纹联合匹配，不调用模型/API；高度相似图仍可能误拦，可在面板测试 |
| 相似图拦截距离 | -1 | 默认关闭 dHash；可从 0 或 1 测试，最大 4，可能误拦 |
| 单图检查上限 | 16 MiB | 超限由检查失败策略处理 |
| 检查失败时禁止发送 | 开 | 文件不可读、损坏、超限或不安全远程地址时拒发该图片消息 |
| 拦截提示 | 图片不能发送，本次请求终止且不要重试 | 本轮固定终止反馈，每个接收会话至多提示一次；留空静默拦截，不要自定义成重试建议 |

禁发策略对管理员同样生效，避免模型借管理员身份绕过。添加/解除才需要管理员权限。

## 边界与兼容性

1. **不是人脸识别，也不是任意改图检测。** 文件指纹拦相同文件；像素指纹覆盖无损格式转换；默认转码保护通过比例、边缘与颜色联合比较近似版本，非数学保证。大幅裁剪、加字、拼图及动图后续帧不保证命中，高度相似画面可能误拦。相似整理不判断“是不是同一个人”。
2. 不解析只有平台消息 ID 的服务端转发、不检查二维码/链接所指向的文件，也不阻止有人手动发送图片。
3. 直接调用 QQ SDK/HTTP API、绕开 AstrBot 发送方法的插件不在拦截范围内；它不是宿主机沙箱。隔离也不限制群成员手动转发，不阻止 AI 用文字描述图片，无法追溯撤回过去已经发出的内容。
4. AstrBot 目前没有覆盖所有直接发送的统一出站钩子，因此本插件在内存中包装已加载的事件/适配器发送方法及内置发消息工具。**不修改 AstrBot 核心文件**。其他插件若在安装之后替换同一方法，需要重载本插件；框架升级后应重新验证。
5. 远程检查拒绝非公开 IP、带凭据 URL 和非 HTTP(S) 协议，并对重定向和 DNS 结果校验；受大小/时限限制。检查成功的远程图片以已检查字节发送，避免二次下载换图。远程图片文件附件因适配器差异默认拒绝；可改用标准图片消息。
6. 长期禁发列表保存哈希、低分辨率视觉指纹和简短原因；不复制完整原图。数据位于 `data/plugin_data/astrbot_plugin_image_guard/denylist.db`，不会写入仓库或安装 ZIP。视觉指纹也属于图片衍生数据，请勿公开分享。
7. 开启时会读取待发图片；大图片、远程图片和相似匹配会增加时间/内存开销。纯文字、语音、普通非图片附件不受图片检查影响。
8. 相册数据库 `history.db`、独立副本 `library/` 和回收站 `trash/` 位于同一插件数据目录。恢复日志可能含原图片引用、base64 图片和受影响的聊天内容，仅供本机撤销使用；彻底删除相应图片会清除这些恢复记录。请勿将插件数据目录、截图、真实照片或数据库提交到公开仓库。
9. 文件删除仅处理 `data/temp/` 与本插件图片库内的已校验文件，不移动外部路径或其他插件文件。回收站不会自动清空，卸载也不会自动销毁图片历史。

## 开发与验证

```bash
python -m pip install -r requirements.txt ruff
python -m unittest discover -s tests -v
ruff check .
ruff format --check .
```

测试图片由代码生成，不包含真实用户照片。包含文件副本、编码/格式转换、表情库黑名单联动、嵌套消息、通用工具、主动消息、流式发送、卸载恢复和读取边界测试。

设计参考 AstrBot 官方消息事件/发送接口，以及 `astrbot_plugin_stealer` 的 SHA-256 黑名单存储约定；这是独立实现，不依赖其运行实例。
